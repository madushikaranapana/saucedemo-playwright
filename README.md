# SauceDemo Automation (Playwright + TypeScript)

Automated tests for the [SauceDemo](https://www.saucedemo.com/) shopping site. The suite covers login, product selection, cart changes, checkout, order confirmation, mouse actions, session isolation, timeouts and a negative login case.

## Prerequisites

- **Node.js v18 or newer** (check with `node -v`)
- **npm** (comes with Node.js)
- **Java 8 or newer** (only needed to generate the Allure report, check with `java -version`)
- **Internet access** (tests run against the public site `https://www.saucedemo.com/`)
- About 500 MB of disk space for the browser download

No accounts, API keys or `.env` file are needed. The test login (`standard_user` / `secret_sauce`) is stored in `src/test-data/credentials.json`.

## Setup

```bash
# 1. Go to the project folder
cd saucedemo-playwright

# 2. Install dependencies (Playwright, TypeScript, csv-parse, Allure)
npm install

# 3. Install the Chromium browser
npx playwright install chromium
```

> `csv-parse` is already listed in `package.json`, so `npm install` installs it. You do not need to run `npm install csv-parse@latest` separately.

On a fresh Linux machine or CI, use `npx playwright install --with-deps chromium` instead of step 3.

## Running the tests

| Command | What it does |
| --- | --- |
| `npm test` | Run all tests (headless) |
| `npm run test:headed` | Run with a visible browser |
| `npm run test:ui` | Open Playwright UI mode |
| `npm run test:debug` | Run with the Playwright Inspector |
| `npm run test:e2e` | Run only the end-to-end purchase test |
| `npm run report` | Open the last HTML report |
| `npm run allure:serve` | Build and open the Allure report (run tests first) |

Run one file or filter by test name:

```bash
npx playwright test tests/login.spec.ts
npx playwright test -g "negative"
```

### Choose the customer for the end-to-end test

By default the first row of `customers.csv` is used. To pick another row (0 = first):

```bash
# macOS / Linux
CUSTOMER_INDEX=2 npm run test:e2e

# Windows PowerShell
$env:CUSTOMER_INDEX=2; npm run test:e2e
```

## What each test covers

| Test file | What it checks |
| --- | --- |
| `login.spec.ts` | Login with a valid user and landing on the inventory page |
| `product-selection.spec.ts` | Adds products from `products.json`, checks names, prices and cart badge |
| `cart.spec.ts` | Cart has 3 items, remove one, 2 remain |
| `checkout.spec.ts` | Checkout for each customer in `customers.csv`, checks item total, 8% tax, total and confirmation |
| `e2e-purchase.spec.ts` | Full flow from login to order confirmation (45 s timeout) |
| `mouse-interactions.spec.ts` | Hover, double-click and right-click |
| `session-isolation.spec.ts` | A new browser context is not logged in and is sent to the login page |
| `negative-login.spec.ts` | Wrong credentials show an error and block access |
| `timeouts.spec.ts` | Confirms the configured timeouts are in effect |

## Allure reporting

The suite also produces an [Allure](https://allurereport.org/) report, in addition to the Playwright HTML report.

**One-time setup** (skip if you already ran `npm install` and the packages are in `package.json`):

```bash
npm install -D allure-playwright allure-commandline
```

**Generate and view the report:**

```bash
npm test                  # runs the tests and creates the allure-results folder
npm run allure:serve      # builds the report and opens it in your browser
```

Or save the report as a folder:

```bash
npm run allure:generate   # creates the allure-report folder
npm run allure:open       # opens it
```

The report shows each test's status, duration and steps (including the named `test.step()` blocks in the E2E test). Screenshots and traces from failed tests are attached automatically.

The `allure-results` and `allure-report` folders are generated files and are ignored by Git.

## Configuration

Timeouts are set in `playwright.config.ts`:

| Setting | Value |
| --- | --- |
| Test timeout | 30 s |
| Assertion timeout | 5 s |
| Action timeout | 10 s |
| Navigation timeout | 15 s |

- The E2E test overrides its timeout to 45 s because it is the longest test.
- No fixed sleeps (`waitForTimeout`) are used. The tests rely on Playwright's auto-waiting.
- Reporters: console list, Playwright HTML report (`playwright-report/`) and Allure (`allure-results/`).
- Screenshots and traces are saved on failure to `test-results/`.
- To view a trace: `npx playwright show-trace test-results/<test-folder>/trace.zip`

## Test data

- `products.json`: product names and expected prices.
- `customers.csv`: columns `firstName,lastName,postalCode`. Add rows to test more customers.
- Pricing rule: tax is 8% of the item total. For the two remaining items, the item total is $45.98, tax $3.68, total $49.66.

## Known limitations

- **Hover:** the site shows no visual change, so the test only checks nothing breaks.
- **Right-click:** the browser's native menu cannot be inspected, so the test checks that nothing happens.
- **Public demo site:** if `saucedemo.com` is slow or down, tests will fail with timeouts.

## Running in CI

Set the `CI` environment variable. The config then enables 1 retry and 2 workers.

```bash
npm ci
npx playwright install --with-deps chromium
npx playwright test
```

Save the `playwright-report/`, `test-results/` and `allure-results/` folders as build artifacts. To build the Allure report in CI, Java must be available, then run `npm run allure:generate`.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `Executable doesn't exist` | Run `npx playwright install chromium` |
| Missing libraries on Linux | Run `npx playwright install --with-deps chromium` |
| Timeouts or `ERR_NAME_NOT_RESOLVED` | Check your internet, proxy or firewall |
| `CUSTOMER_INDEX ... is invalid` | Use a number from 0 to (number of CSV rows - 1) |
| Report won't open | Run `npm run report` after a test run |
| Allure error: Java not found | Install Java 8 or newer and check with `java -version` |
| Allure report is empty | Run `npm test` first so `allure-results/` exists, then run `npm run allure:serve` |
